# 故障排除

按场景排查。仍无法解决时，到 [NeoLinker 仓库](https://github.com/camthink-ai/NeoLinker/issues) 提交 issue，并附上导出的会话历史与环境信息（操作系统与版本、NeoLinker 版本、是否有蓝牙适配器等）。

## BLE 扫不到设备

**现象**：扫描页 BLE 一路长时间为空。

- 确认设备确实处于**配置模式**（进入方式见设备随附说明）；
- 确认自检页 **BLE 一路就绪**：系统蓝牙已开启、适配器驱动正常；台式机建议使用 USB 蓝牙适配器；
- **拉近距离**重试——RSSI 过低时广播可能收不到；
- 确认没有其他主机正在配置这台设备（设备广播 BUSY 标志时不易被发现）；
- 注意 NE101 的**配置窗口**：设备上电后约 60 秒内可被配置（蓝灯快闪），约 1 分钟无操作会自动休眠——短按配置键唤醒后重试；
- EK410：长按 **PAGE** 键约 2.5 秒进入 BLE 配网（状态灯青色闪烁），广播名为 `EK410-XXXXXX`。SoftAP 与 BLE 窗口互斥，开着热点时 BLE 不会出现；
- 换一台设备交叉验证，区分是设备侧还是电脑侧问题。

## 扫描列表里机型显示为"未知型号"

**现象**：设备出现在列表里，但机型一栏不是具体型号。

- 应用版本过旧，还不认识这台设备：已发布的 v0.3.0 只支持 NE101 / NE301 / NE503，EK410 支持在后续版本提供。到 [GitHub Releases](https://github.com/camthink-ai/NeoLinker/releases) 更新到最新版本；
- 版本号显示在应用侧栏底部。注意已发布的 v0.3.0 有一个已知问题：侧栏和导出回执里显示的版本是 v0.2.0，属显示错误，后续版本已修复。

## 蓝牙配对失败 / 连接超时

**现象**：点连接后 Windows 配对失败，或连接长时间无响应。

- 先在 Windows 蓝牙设置里**删除已存在的配对记录**（macOS 在"系统设置 › 蓝牙"里操作），回到扫描页重连；
- BLE 链路使用加密，配对弹窗务必点确认（不要忽略）；
- 距离与干扰：远离微波炉 / USB 3.0 hub 等干扰源；
- 反复失败时重启电脑蓝牙（关-开飞行模式或重启蓝牙服务）后重试。

## softAP 连不上

**现象**：softAP 一路能看到 SSID，但后续连接 / 通信失败。

- 应用会自动连接设备热点（当前 NE101 热点名多为 `<机型>_<地址后缀>`，如 `NE101-P_BBC6DC`）；连接期间当前 Wi-Fi 会暂时断开，结束后自动恢复；
- EK410 的热点带 WPA2 密码，应用会自动连接；若要手动连接，密码是 `12345678`（设备屏幕的引导页上有显示），管理地址为 `http://192.168.4.1`；
- 若连接失败，可先手动断开电脑上的其他 Wi-Fi 再重试；
- 若手动访问设备，默认地址见[发现设备](./2-discover-devices.md)中的地址表；
- 设备同一时间只服务一条配置连接——若他机正在配置，设备会示忙（BUSY），请稍后再试。

## 下发失败（错误码）

**现象**：下发后结果页报错。

对照[配置设备](./3-provision-device.md)中的错误码表：

- `INVALID_ARGUMENT`——按表单校验提示修正；
- `SECTION_NOT_SUPPORTED` / `FIELD_NOT_SUPPORTED`——该机型 / 模块不支持此配置节或字段，去掉后重试；
- `BUSY`——稍候重试，确认无其他主机在配置同一设备；
- `STORAGE_FAILED`——先看错误详情：EK410 走 softAP 通道时出现 `wifi associate failed`，说明 Wi-Fi 关联失败（多半是密码错误）；否则重试，反复出现说明设备存储异常，需进一步检修。

## 提示缺少 WebView2（Windows）

**现象**：启动或打开 NE503 管理页时提示 WebView2 缺失。

安装 [WebView2 Evergreen 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)（x64）后重启应用。详见[安装与环境](./1-install-setup.md)。

## NE503 在局域网里发现不到

**现象**：设备与电脑都在网内，LAN 一路仍为空。

- 确认两者在**同一网段**（CT-Disc 使用 UDP 组播，跨网段默认不可达）；
- 检查网内交换机 / 路由器是否放行组播；
- 等待数秒——设备周期性播报 `ct-announce`，有间隔；
- 确认设备固件为支持 CT-Disc 的版本。

## 下发成功了，但设备没连上 Wi-Fi

多数机型上这不是工具故障：NeoLinker 只负责把配置**写入设备并持久化**，不验证运行时联网。请检查：

- SSID / 密码是否正确（若设备仅支持 2.4 GHz，确认路由器开启了该频段——以设备手册为准）；
- 设备侧日志或设备本地页面确认关联状态；
- 路由器侧 MAC 过滤 / 黑白名单。

例外是 EK410 的 softAP 通道：设备会先试连 Wi-Fi，连不上时下发本身就失败（`STORAGE_FAILED`），不会出现"下发成功但没联网"。

## macOS 上的问题

macOS 版是实验性支持，只通过了 CI 验证，尚未在真机上运行过。

- **应用打不开、提示无法验证开发者**：构建产物未签名。在"访达"中找到应用，右键选择"打开"，再确认一次；
- **自检页 softAP 一路不可用**：确认 Wi-Fi 已打开。Wi-Fi 关闭时扫描页会显示受限状态，并提供"打开系统 Wi-Fi 设置"按钮；
- **softAP 一路一直为空**：macOS 10.15 及以后，Wi-Fi 扫描需要系统的"定位服务"授权，未获授权时这一路会一直为空且不报错。到"系统设置 › 隐私与安全性 › 定位服务"检查 NeoLinker 是否被允许；这项行为尚未在真机上确认，必要时改用 BLE 通道或扫码录入；
- **摄像头扫码不可用**：确认已在"系统设置 › 隐私与安全性 › 相机"中允许 NeoLinker 访问摄像头；仍不行时切换到"上传图片"识别；
- **内嵌管理页加载失败**：失败面板上提供转用系统浏览器打开的按钮，可改用系统浏览器继续。
