# 配置设备

从列表选中设备那一刻起，就进入了一次**相位驱动的配置会话**：

```mermaid
flowchart LR
    A["连接"] --> B["读能力"] --> C["逐模块配置"] --> D["下发"] --> E["结果回执"]
```

一屏一相位；连接意外断开时应用自动检测并**原位重连**，恢复后接着走，迟到的重复结果被幂等丢弃。

## 1. 连接与配对

- **BLE 通道**：使用加密链路。Windows 弹出蓝牙配对提示时确认即可——配对建立的绑定关系是链路加密的基础；
- **softAP 通道**：按应用指引把电脑 Wi-Fi 切到设备热点（`CT-AP-<地址后缀>`）；
- **LAN 通道（NE503）**：同网段即可直连。

连接建立后，应用先读取**设备信息**（机型、序列号等），再读取**能力声明**。

## 2. 能力读取

设备会报告自己支持哪些配置模块、每个模块有哪些字段与约束。随后的配置表单完全由这份报告生成——**设备不支持的模块不会出现，支持的模块预填当前值**，你可以只改想改的部分。

## 3. 配置节表单

CT-Prov/1 定义了七类配置节。设备实际出现哪些，取决于机型与所装通讯模块：

| 配置节 | 用途 | 常见机型 |
| ---- | ---- | ---- |
| `wifi` | Wi-Fi 接入：SSID、密码（可触发设备端扫描选网） | NE101 / NE301 |
| `cellular` | 蜂窝（CAT1）拨号：APN 等 | NE101 / NE301 |
| `halow` | Wi-Fi HaLow 低功耗长距接入 | 按模块 |
| `ethernet` | 以太网口配置 | 按机型 |
| `comm` | 网络选择器：指定优先使用哪个上网通道 | NE101 / NE301 |
| `mqtt` | MQTT 服务：broker 地址、端口、主题等 | NE101 / NE301 / NE503 |
| `webhook` | Webhook 推送：URL、事件等 | NE101 / NE301 |

填写时的通用行为：

- **密码类字段**可切换明文核对，避免产线错输；
- **payload 预览**可展开，核对即将下发的 JSON 原文；
- 取消离开时**草稿保留**，回来接着填。

## 4. 交付

点**下发**后，应用把勾选的配置节逐模块写入设备。交付语义需要了解：

- **整节覆盖写**——每个配置节按本次表单整体覆盖，幂等：重复下发同一内容结果一致；
- **成功即已持久化**——设备返回成功表示配置已写入非易失存储，重启不丢；
- **不验证联网**——工具不替你确认设备能否真的连上 Wi-Fi / broker；运行时结果由设备日志、设备本地页面或平台侧呈现。

### 常见错误码

| 错误码 | 含义 | 常见处理 |
| ---- | ---- | ---- |
| `INVALID_ARGUMENT` | 参数类型 / 范围 / 组合不合法 | 按表单校验提示修正后重试 |
| `SECTION_NOT_SUPPORTED` | 配置节不受支持或不可配置 | 该机型不含此模块——去掉此节再下发 |
| `FIELD_NOT_SUPPORTED` | 含能力声明之外的字段 | 刷新能力后按新表单填写 |
| `BUSY` | 设备正在服务其他连接或扫描 | 等待片刻重试，或确认没有别的主机在配置它 |
| `STORAGE_FAILED` | 配置持久化失败 | 重试；反复出现则检查设备存储状态 |
| `INVALID_MESSAGE` / `UNSUPPORTED_VERSION` / `UNSUPPORTED_OPERATION` / `INTERNAL_ERROR` | 消息 / 版本 / 操作不兼容或设备内部错误 | 升级设备固件与应用版本后重试 |

## 5. 断链与重连

配置过程中链路意外断开（设备休眠、距离过远、热点切换等）时：

- 应用标记**链路丢失**并尝试**原位重连**，不丢已填表单；
- 重连成功后会话从断点继续；
- 会话已结束后迟到的结果消息被幂等丢弃，不会污染回执。
